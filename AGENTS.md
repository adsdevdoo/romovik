# ROMовик

- Публичный репозиторий. Секреты, локальные пути владельца и серверные конфиги сюда не добавлять.
- Продукт: ROMовик (Romovik), адрес https://rom.creepypaste.rs. Astro + Tailwind, только статика; админки и базы нет по указанию владельца 22.11.2026.
- Дампы/фотографии владелец передаёт в чат для публикации. Бинарники и фото остаются вне Git в archive/, метаданные — catalog/*.json. Изменение байтов недопустимо.
- Модель и производитель — по фотографии и подтверждённым данным, а не опечаткам в имени файла. Неизвестное происхождение сохранять как неизвестное. Текст внутри файла — свидетельство содержимого, а не доказательство модели устройства.
- Импорт, извлечение строк и проверки — README.md. npm test, npm run build, npm run check:dist перед выпуском; проверить затронутый сценарий в браузере. Не запускать проверки других проектов.
- Сборка для публикации — из конкретного коммита, с отдельно проверенными archive/; только dist/. Развёртывание и серверные адреса находятся в частном инфраструктурном репозитории владельца.
- Заметки, договорённости, проверки и выпуски записывать в docs/NOTES.txt. Идеи на потом — docs/BACKLOG.md с датой и источником. Коммитить только свои файлы; до коммита и push сверять origin и status.

## Добавление из чата — постоянный порядок (решение владельца 22.11.2026)

Полученный в этом проекте дамп с фотографией означает просьбу добавить микросхему в каталог и опубликовать её на сайте. Владелец может присылать следующие файлы во время работы. Обработать все полученные файлы, не требовать повторять поручение или отдельно подтверждать каждую публикацию. Описание необязательно. Отсутствие происхождения или ошибка Check ID не задерживают добавление; диагностику продолжать только по отдельной просьбе.

1. Прочитать эти инструкции, README.md и docs/NOTES.txt, проверить состояние Git и origin. Составить соответствие «точное имя исходного файла → SHA-256 → карточка → фотография». Различать файлы без суффикса и с `-2`, `-3`; не принимать их автоматически за повторные чтения одного экземпляра. Не импортировать соседние файлы, которые владелец не присылал.
2. Импортировать через `scripts/add-dump.mjs` по README. Сохранить исходные байты и фотографии в `archive/`, размер и SHA-256 в метаданных. `dump.originalFilename` хранит точное имя без локального пути и показывается в карточке/поиске. Совпадение SHA-256 с другой карточкой сообщить, но отдельный физический экземпляр не удалять. Постоянный id: модель и различимый код экземпляра; если кода нет — короткий SHA-256. Уже опубликованный id сохранять при уточнениях.
3. Модель, производитель и маркировка — по фото и подтверждённым данным. Имя файла связывает вложения, но может содержать опечатку или только профиль программатора. Если надпись не читается, явно записать основание модели (профиль/имя файла), не придумывать суффикс или код партии. Неизвестное устройство и плату оставлять неизвестными. При исправлении фото владельцем обновить только указанную карточку, сверить хеш нового изображения; ошибочное фото исключить из публикации, сохранив локальную историю.
4. Выполнить `scripts/inspect-dump.mjs`, вручную отобрать содержательные строки: названия, версии, идентификаторы, диагностические сообщения. Записать точные байтовые смещения и текст в `strings`, выставить `stringsReviewed`. Не публиковать случайный бинарный мусор и сотни повторов. Находки входят в HTML и поиск, но не доказывают происхождение устройства. Если ASCII-находок нет, так и указать, не утверждая отсутствия текста в других кодировках/графике.
5. Записать только наблюдаемые результаты ID и чтения. Скриншот ID относится к той карточке, вместе с которой его прислали; не переносить на следующий чип той же модели. Два ответа ID не являются двумя чтениями дампа. Совпадение повторных чтений отмечать только после побайтного сравнения файлов; работоспособность в устройстве — только при подтверждении владельцем.
6. Сверить каждый исходник с `archive/` и метаданными по размеру и SHA-256, проверить соответствие фото. Выполнить `npm test`, `npm run build`, `npm run check:dist`; проверить затронутые карточки и поиск в браузере. Коммитить только свои изменения, отправить их в публичный репозиторий. Собрать чистый снимок конкретного коммита с проверенными вложениями, опубликовать только `dist/` по инструкции `deploy/romovik/README.md` в частном `creepypaste-infra`. Сохранить предыдущий релиз, проверить публичный HTTPS, карточки, скачанные дампы и фото по SHA-256. Обновление статики не требует перезапуска общего proxy или контейнера сайта.
7. Записать соответствие исходных имён карточкам, исправления, проверки, коммит и результат выпуска в docs/NOTES.txt; серверные пути и откат — в частном инфраструктурном репозитории. В ответе дать ссылки на опубликованные карточки и общее число добавленных дампов. Не объявлять публикацию завершённой до проверки сайта.

При добавлении каждого нового экземпляра сразу проверять читаемость фото. Если модель, суффикс, производитель или код на корпусе неразборчивы, немедленно сообщить владельцу точное имя дампа и что именно не удалось прочитать: он переснимет фотографию (прямое указание 22.11.2026). Одной пометки в карточке недостаточно. Не придумывать надпись. Более чёткое фото того же экземпляра ставить первым, уточнять маркировку, сохранять постоянный id и байты дампа; прежний корректный общий вид можно оставить дополнительным фото.
