# ROMовик

Открытый архив дампов ПЗУ: **https://rom.creepypaste.rs/**.

Astro + Tailwind CSS, серверный HTML для поисковых систем, Java/Javalin API и MongoDB. Поиск по маркировке, производителю, описанию, SHA-256 и текстовым находкам. Посетители отправляют BIN и фотографии через `/submit/`; закрытая очередь `/moderation/` требует отдельной учётной записи. Только одобренные дампы доступны публично, контакты отправителей не публикуются.

## Сервер и база

Java 21+, Maven; модули `rs.adsdev.helpers:mongodb` и `javalin-app` закреплены на выпуске `1.0.16-20261105.133233-67`. Доступ к Maven-репозиторию helpers настраивается в пользовательском settings.xml (на рабочей машине профиль `ohm`); адреса и учётные данные не входят в этот публичный проект.

```sh
cd server
mvn -Pohm test package
MONGO_URI='mongodb://localhost:27017/romovik' ASSET_DIR='../archive' java -jar target/romovik-server-1.0.0.jar seed ../catalog
MONGO_URI='mongodb://localhost:27017/romovik' ASSET_DIR='../archive' SITE_ORIGIN='http://localhost:4321' java -jar target/romovik-server-1.0.0.jar
```

Для одобрения нужны транзакции MongoDB (replica set или sharded cluster). URI можно читать из `MONGO_URI_FILE`. `seed` — первоначальная проверяемая миграция, существующие карточки не переписывает. `import <record.json>` добавляет один экземпляр и назначает следующий номер атомарно в базе. Файлы перед ним размещаются в `ASSET_DIR/<id>/`, их размеры, хеши и выбранные строки проверяются. Вывод import — окончательная карточка с номером из базы.

Модератор создаётся только операторской командой `create-admin`: пароль читается со stdin, не из аргумента. Первый вход требует смены временного пароля. Публичной регистрации модераторов нет. Сессии HttpOnly/Secure/SameSite, CSRF, ограничения попыток входа и размеров/частоты/одновременности загрузок; отклонённые файлы остаются закрытыми. Модератор редактирует описание, подтверждает маркировку, выбирает точные ASCII-фрагменты и одобряет либо отклоняет заявку. Одобрение и номер — одна транзакция.

Интеграционные тесты: `TEST_MONGO_BASE='mongodb://localhost:27017/' mvn -Pohm test` (отдельный тестовый Mongo endpoint). Тест создаёт случайную `romovik_test_*` базу и удаляет только её. Проверяются приватность, CSRF, гонка одобрения, неизменность байтов, отозванные сессии и отклонение.

## Запуск

```sh
npm ci
npm run fetch-assets
npm run dev
```

В проекте закреплён локальный Node 22.23.4: `npm ci` устанавливает его в `node_modules`, системная Node не меняется. Для начальной установки нужен Node 22+ и npm 10+. Предупреждения engines при запуске npm из более старой Node не влияют на последующие npm scripts: они используют закреплённую версию. Install scripts нужны для установки локального runtime.

Источник опубликованных данных — MongoDB. `catalog/*.json` — проверяемый снимок: `npm run sync-catalog` обновляет его с сайта. Дампы и фотографии хранятся в игнорируемом `archive/<id>/`; `fetch-assets` восстанавливает опубликованные файлы и сверяет размеры/SHA-256. Изменившийся локальный файл не перезаписывается. `API_ORIGIN` задаёт адрес Java API (по умолчанию http://127.0.0.1:8080).

```sh
npm test
npm run build
npm run check:dist
npm run preview
```

Результат — серверная сборка `dist/`, запуск `HOST=127.0.0.1 PORT=4321 node dist/server/entry.mjs`. Для `check:dist` эта сборка и Java API должны работать: `CHECK_URL` по умолчанию http://localhost:4321. Проверка сверяет HTML, ссылки, sitemap, 404 и байты всех вложений с локальным снимком. `SITE_URL` задаёт основной HTTPS-адрес при сборке; по умолчанию https://rom.creepypaste.rs. Dockerfile.web и server/Dockerfile используют закреплённые базовые образы; серверные настройки и откат хранятся отдельно.

## Добавление

### Даташиты

Обязательный шаг для **каждой новой микросхемы**: сразу подобрать даташит и добавить ссылку в карточке при той же публикации, без отдельной просьбы владельца. Сначала проверить реестр и использовать уже сохранённый подходящий PDF; если его нет — скачать и проверить новый. Один документ для нескольких экземпляров хранится один раз; совпадающий SHA-256 означает повтор даже при другом имени файла или URL источника.

Документы производителя хранятся один раз в `public/datasheets/`; общий реестр — `src/lib/datasheets.json`. Карточки подбирают PDF по явной паре «модель + производитель» и ссылаются на один файл для всех подходящих экземпляров. Модель берётся с корпуса, а не из имени BIN или профиля чтения: M27512 и M27C512 нельзя автоматически считать одной моделью.

При добавлении модели найти оригинальный документ производителя (для снятых с производства — его копию в архиве), открыть PDF и проверить семейство, корпус и применимость редакции. Сначала переиспользовать подходящий документ из реестра; иначе скачать PDF без изменения байтов и добавить название, издателя, редакцию, исходный URL, дату, число страниц, размер и SHA-256. Имя — `<id>-<первые 12 символов SHA-256>.pdf`. Повторный SHA-256 и неоднозначные соответствия запрещены проверкой. Не выдавать документацию семейства за подтверждение каждого старого суффикса: у AMD Am27C256 используется редакция 08007 Rev. G (1993), её таблица не перечисляет старый -205DC.

`npm run validate` проверяет все файлы реестра; `check:dist` проверяет ссылки в каждой карточке, MIME и SHA-256 PDF, скачанных с сайта. Недостающий даташит сообщить владельцу, чужой или предположительно подходящий документ не подставлять.

Каталог всегда идёт в порядке добавления: новый дамп — последний. Постоянный номер `sequence` назначается автоматически и сохраняется при уточнении маркировки или фото. Номер и исходное имя видны в списке и карточке. Поиск и фильтры сохраняют порядок; альтернативной сортировки нет.

Владелец по-прежнему может передавать файл, фото и описание в чат. Перед импортом синхронизируйте снимок с базой. CLI ниже готовит локальные метаданные и проверяет байты; финальный номер назначает Java-команда `import`, затем снова выполните sync-catalog. Посетительские заявки проходят через форму и модерацию. В PowerShell используйте `npm.cmd`, поскольку `npm.ps1` может поглощать параметры.

Постоянный порядок обработки присланных файлов и публикации — [AGENTS.md](AGENTS.md). Исходное имя сохраняется в `dump.originalFilename` без локального пути, показывается в карточке и участвует в поиске; файлы с суффиксами `-2`, `-3` связываются с фото отдельно.

Перед импортом проверить все надписи на корпусе. Если что-либо не читается, сразу сообщить владельцу точное имя файла и неразборчивую часть. До уточнения микросхему не добавлять в каталог и не публиковать. Владелец может прислать более чёткое фото или написать маркировку текстом — пересъёмка необязательна. После уточнения продолжить добавление без повторного запроса разрешения.

```sh
npm run add-dump -- --file /path/to/read.bin --id unique-chip-id --chip NMC27C256Q-25 --manufacturer "National Semiconductor" --type EPROM --photo /path/to/photo.png
```

Необязательные параметры: `--description`, `--label`, `--package`, `--device`, `--board`, `--origin known|uncertain|unknown`, `--profile`, `--programmer`, `--date YYYY-MM-DD`. `--photo` можно повторять. `--verify` принимает второй файл чтения: отметка о совпадении появляется только после побайтной проверки. Без него проверка чтения считается незаписанной; работоспособность в устройстве не предполагается.

Новый id постоянен: ссылки на карточку не должны ломаться. Команда не перезаписывает существующую запись или её исходники. Совпадение содержимого с другим ПЗУ выводится отдельно, но не удаляет его историю. Если импорт остановился на ошибке копирования, неполную новую папку следует проверить до повторного запуска; существующие исходные файлы не изменяются.

## Строки внутри дампа

```sh
node scripts/inspect-dump.mjs /path/to/read.bin
```

Инструмент извлекает кандидаты ASCII с точными смещениями, включая последнюю строку файла. Бинарные данные могут случайно выглядеть как текст: подходящие строки отбираются вручную в поле `strings` карточки (`offset`, `encoding: "ASCII"`, `text`). `stringsReviewed` отмечает проведённый просмотр. Сборка проверяет каждый опубликованный фрагмент по исходным байтам. Никакие символы или пробелы внутри выбранного фрагмента не заменяются. Эти строки входят в обычный HTML карточки и в поиск. Другие кодировки и изображения букв этим сканером не распознаются.

## Сохранность

`npm run validate` проверяет схему, SHA-256, размеры, фотографии и выбранные строки. Сборка останавливается при отсутствующем или изменённом файле. Исходные бинарники, контакты, секреты и конфигурация серверов не входят в Git. Файлы доступны публично только через записи, одобренные в MongoDB; каталоги заявок не являются static root. Резервные копии включают MongoDB и неизменяемые вложения; порядок восстановления ведётся отдельно от публичного репозитория.

Соглашения и результаты работы — `docs/NOTES.txt`. Просьбы об уточнении карточек — GitHub Issues.
